##  Назначение документа

Это **практическое руководство** по прохождению плана [[От нуля до Middle Embedded, IoT Engineer]]]". План отвечает на вопрос "ЧТО учить", этот документ — на вопрос "КАК учить". Без этой инструкции план останется красивой картинкой в Obsidian.

**Целевая аудитория:** ты сам через 3 месяца, когда забудешь, зачем всё это затеял.

---

## 🎯 Общие принципы прохождения

### Принцип 1: "Один сниппет — одно понимание"

**Правило:** Не переходи к следующему сниппету, пока не можешь объяснить текущий без подглядывания.

**Как проверить:**
1. Закрой редактор кода
2. Открой пустой файл
3. Напиши сниппет по памяти
4. Объясни вслух каждую строку

Если застрял на пункте 3 — **не иди дальше**. Вернись, разберись, повтори.

**Почему это важно:** Нейронка пишет код за секунду. Ты пишешь — за 20 минут. Но через 20 минут ты **понимаешь**, а нейронка — нет.

---

### Принцип 2: "Теория только для текущей задачи"

**НЕ делай так:**
> "Сегодня выучу весь закон Ома, потом все протоколы, потом весь C"

**Делай так:**
> "Сейчас подключаю LED. Мне нужно знать: какой резистор поставить? → Закон Ома. Всё, остальное потом."

**Правило:** Теория изучается **только** когда возникает практическая задача, требующая этого знания.

**Пример:**
- Задача: подключить LCD 1602
- Нужная теория: распиновка HD44780, 4-битный режим, тайминги Enable
- НЕ нужная теория: как работает SPI, архитектура ARM, указатели в C

---

### Принцип 3: "Ломай осознанно"

**Правило:** Каждый сниппет должен быть сломан минимум 3 раза **перед** тем, как считается завершённым.

**Как ломать:**
1. **Логическая поломка:** отключи один провод, поменяй пины местами, убери подтяжку
2. **Кодовая поломка:** измени константу, убери `delay()`, поменяй HIGH на LOW
3. **Физическая поломка (осторожно!):** замени резистор 220Ω на 1кОм, подключи питание через диод

**Что записывать:**
```markdown
## Поломка #1: Отключил RW от GND
**Симптом:** Квадратики есть, текст не меняется
**Причина:** HD44780 перешёл в режим чтения
**Решение:** Подключил RW → GND
**Вывод:** RW — переключатель направления шины. На ESP32 с I2C не нужен.
```

---

### Принцип 4: "Dev-log = проблемы, а не достижения"

**НЕ пиши так:**
> "Сегодня подключил LCD, всё работает, молодец я"

**Пиши так:**
> "LCD не показывал текст. Оказалось, RW не на GND. Теперь знаю: без RW дисплей не принимает команды."

**Правило:** Запись в dev-log делается **только** если ты сам создал проблему и решил её.

**Почему:** Через 3 месяца ты забудешь, как работает LCD. Но ты не забудешь, **почему** RW должен быть на GND — потому что ты сам на этом застрял.

##  Расписание на неделю

**Твоё время:** ~20 часов в неделю
- 3 дня по 5-6 часов (основные сессии)
- 3 дня по 0.5-1 часу (поддерживающие сессии)
- 1 день выходной

### Основные сессии (5-6 часов)

**Структура:**
```
Час 1: Теория для текущей задачи (чтение даташита/документации)
Час 2-3: Практика (подключение + код)
Час 4: Ломай (3 поломки + решения)
Час 5: Dev-log + Git коммит
Час 6 (если есть): Планирование следующей сессии
```

**Пример (LCD 1602):**
- Час 1: Читаю распиновку HD44780, понимаю, зачем нужен RW
- Час 2-3: Подключаю LCD, пишу код, добиваюсь вывода текста
- Час 4: Отключаю RW → чиню. Меняю пины D4-D7 → чиню. Убираю резистор подсветки → чиню
- Час 5: Записываю 3 поломки в dev-log, коммичу в Git
- Час 6: Планирую: следующий сниппет — DHT11, нужно прочитать про single-wire

### Поддерживающие сессии (0.5-1 час)

**Что делать:**
- Повторить сниппет по памяти (15 мин)
- Прочитать 1 страницу документации ESP-IDF (15 мин)
- Записать 1 мысль в dev-log (5 мин)
- Проверить Git, сделать мелкий коммит (10 мин)

**НЕ делать:**
- Начинать новый сниппет
- Читать много теории
- Писать большой код

**Почему:** Поддерживающие сессии — это **закрепление**, а не прогресс.

## 🤖 Интеграция нейросетей

У тебя 3 нейронки: **Qwen, DeepSeek, Perplexity**. Каждая для своей задачи.

### Qwen — Код и отладка

**Когда использовать:**
- Написать код сниппета
- Объяснить, как работает конкретная строка
- Найти ошибку в коде
- Предложить, как сломать сниппет

**Промпт-шаблон:**
```
Напиши код для [задача] на [Arduino/ESP-IDF].
Требования:
1. Объясни каждую строку кода комментарием
2. Укажи, какие пины использовать
3. Предложи 3 способа сломать этот код и как это будет выглядеть
4. Не используй библиотеки, если можно написать вручную
```

**Правило:** Не копируй код blindly. Читай каждую строку, объясняй вслух. Если не понимаешь — спрашивай Qwen до полного понимания.

---

### DeepSeek — Теория и объяснения

**Когда использовать:**
- Объяснить, как работает протокол (I2C, SPI, UART)
- Объяснить концепцию (pull-up, volatile, FSM)
- Объяснить, почему что-то работает именно так
- Перевести технический текст с английского

**Промпт-шаблон:**
```
Объясни [концепция/протокол] простыми словами.
Требования:
1. Начни с аналогии из реальной жизни
2. Покажи, как это работает на уровне битов/байтов
3. Приведи пример кода (минимальный)
4. Укажи типичные ошибки и как их избежать
5. Сравни с альтернативами (если есть)
```

**Правило:** DeepSeek — твой "преподаватель". Если не понял объяснение — проси объяснить по-другому, с другим примером.

---

### Perplexity — Поиск и документация

**Когда использовать:**
- Найти конкретную функцию в ESP-IDF docs
- Найти даташит компонента
- Найти решение конкретной ошибки
- Найти примеры кода на GitHub

**Промпт-шаблон:**
```
Найди в официальной документации ESP-IDF:
1. Функцию для [задача]
2. Пример использования
3. Типичные ошибки
4. Ссылку на источник
```

**Правило:** Perplexity — твой "библиотекарь". Он находит информацию, но не объясняет. Для объяснения — к DeepSeek.

---

### Workflow с нейронками

**Пример (подключение DHT11 на ESP32):**

1. **Perplexity:** "Найди в ESP-IDF docs функцию для чтения GPIO с таймингами микросекунд"
   → Нашёл: `esp_timer_get_time()`, `gpio_set_level()`

2. **DeepSeek:** "Объясни, как работает single-wire протокол DHT11"
   → Объяснил: мастер тянет линию low на 18ms, датчик отвечает бит за битом

3. **Qwen:** "Напиши код чтения DHT11 на ESP-IDF без библиотек"
   → Написал код с комментариями

4. **Ты:** Читаешь код, объясняешь каждую строку вслух. Если не понимаешь — спрашиваешь DeepSeek.

5. **Qwen:** "Предложи 3 способа сломать этот код"
   → Предложил: убрать подтяжку, поменять тайминги, отключить питание на 1 сек

6. **Ты:** Ломаешь, чинишь, записываешь в dev-log.

## 📝 Как вести dev-log правильно

### Формат записи

## [Дата] — [Название сниппета/проекта]

### Задача:
[Что хотел сделать]

### Что сделал:
[Краткое описание действий]

### Проблема #1:
**Симптом:** [Что произошло]
**Причина:** [Почему произошло]
**Решение:** [Как починил]
**Вывод:** [Что понял, как избежать в будущем]

### Проблема #2:
[То же самое]

### Итог:
[Работает/не работает, что дальше]

### Пример реальной записи
## 09.06.2026 — LCD 1602 Parallel

### Задача:
Подключить LCD 1602 к Arduino, вывести текст "Hello World"

### Что сделал:
Подключил по схеме: RS→A0, E→A1, D4-D7→A2-A5, RW→GND, V0→потенциометр.
Загрузил код через PlatformIO.

### Проблема #1:
**Симптом:** Подсветка горит, но экран показывает только квадратики
**Причина:** Не крутил потенциометр. Контраст был на минимуме.
**Решение:** Покрутил потенциометр от края до края, текст появился.
**Вывод:** V0 регулирует напряжение на контроллере HD44780. При 0V контраст минимальный, при 5V — максимальный. Потенциометр — делитель напряжения.

### Проблема #2:
**Симптом:** Текст пропадает при подключении всех пинов D4-D7
**Причина:** Плохой контакт в макетке на пине A3
**Решение:** Пошевелил провод, вставил глубже. Текст стабилен.
**Вывод:** Макетка не всегда надёжна. Если что-то работает "через раз" — проверяй контакты.

### Итог:
LCD работает. Следующий шаг — подключить DHT11 и выводить температуру.
### Правила ведения dev-log

1. **Записывай только проблемы.** Если всё заработало с первого раза — не записывай.
2. **Записывай сразу.** Не откладывай на "потом вспомню".
3. **Пиши своими словами.** Не копируй объяснения нейросетей.
4. **Добавляй фото/скриншоты.** Схема подключения, ошибка в консоли, результат на экране.
5. **Перечитывай раз в неделю.** Это закрепит знания.

## 🔧 Как работать с Git

### Структура репозитория

```
embedded-learning/
├── arduino/
│   ├── snippets/
│   │   ├── lcd-1602/
│   │   │   ├── src/
│   │   │   │   └── main.cpp
│   │   │   ├── platformio.ini
│   │   │   └── README.md
│   │   ├── dht11/
│   │   ── ...
│   └── README.md
├── esp32/
│   ├── snippets/
│   │   ├── blink/
│   │   ├── i2c-scanner/
│   │   └── ...
│   └── README.md
├── dev-log.md
└── README.md
```

### Workflow

1. **Создал новый сниппет:**
   ```bash
   cd arduino/snippets
   mkdir lcd-1602
   cd lcd-1602
   pio init --board uno
   ```

2. **Написал код, заставил работать:**
   ```bash
   git add .
   git commit -m "LCD 1602: базовое подключение, вывод текста"
   ```

3. **Сломал, починил, записал в dev-log:**
   ```bash
   git add .
   git commit -m "LCD 1602: исправил RW pin, добавил объяснения"
   ```

4. **Запушил:**
   ```bash
   git push
   ```

### Правила коммитов

**Формат сообщения:**
```
[Компонент]: [что сделал]

Пример:
LCD 1602: добавил обработку ошибки шины I2C
DHT11: исправил тайминги single-wire протокола
BME280: переписал на C++ класс
```

**НЕ делай так:**
```
git commit -m "fix"
git commit -m "working now"
git commit -m "asdfghjkl"
```

**Делай так:**
```
git commit -m "LCD 1602: подключил RW к GND, текст появился"
git commit -m "DHT11: добавил проверку контрольной суммы"
git commit -m "BME280: обработал таймаут I2C шины"
```

### Если Git кривой

**Проблема:** Git не работает, коммиты не пушатся.

**Решение:**
1. Используй **GitHub Desktop** (графический интерфейс)
2. Или заливай через браузер на GitHub.com
3. Или используй **Obsidian Git** плагин (если ведёшь в Obsidian)

**Главное:** Регулярность важнее идеальности. Лучше кривой коммит каждый день, чем идеальный раз в месяц.

## 🚧 Что делать, когда застрял

### Шаг 1: Остановись

**НЕ делай:**
- Гуглить часами
- Просить нейронку "решить всё за меня"
- Бросать и идти смотреть YouTube

**Делай:**
- Встань, попей воды
- Посмотри на схему/код свежим взглядом
- Запиши, **что именно** не работает

---

### Шаг 2: Локализуй проблему

**Вопросы:**
1. Проблема в **коде** или в **подключении**?
2. Если в коде — на какой строке?
3. Если в подключении — какой провод/пин?

**Метод:**
- Упрощай схему до минимума (только питание + земля)
- Упрощай код до минимума (только blink)
- Добавляй по одному элементу, проверяй после каждого

---

### Шаг 3: Используй нейронки правильно

**НЕ спрашивай:**
> "Почему не работает? Вот весь код и вся схема"

**Спрашивай:**
> "Я подключил LCD к Arduino. Подсветка горит, но текст не появляется. RW подключен к GND, потенциометр крутил. Какие ещё могут быть причины?"

**Порядок:**
1. **Perplexity:** "Типичные ошибки при подключении LCD 1602"
2. **DeepSeek:** "Объясни, как работает пин RW на LCD 1602"
3. **Qwen:** "Напиши минимальный код для проверки LCD без библиотек"

---

### Шаг 4: Запиши в dev-log

**Даже если не решил** — запиши, что пробовал. Через день-два ты или нейронка найдёте решение.

**Формат:**
## [Дата] — [Проблема]

### Проблема:
[Описание]

### Что пробовал:
1. [Действие 1] → [Результат]
2. [Действие 2] → [Результат]

### Что не пробовал:
[Идеи на потом]

### Статус:
[Не решено / Решено]

---

### Шаг 5: Сделай перерыв

**Правило:** Если застрял больше чем на 1 час — закрой ноутбук, иди гулять.

**Почему:** Мозг решает проблемы в фоне. Через 2 часа ты вернёшься и увидишь решение за 5 минут.

## ⚠️ Типичные ошибки и как их избежать

### Ошибка 1: "Скопировал код — работает — пошёл дальше"

**Проблема:** Ты не понял, как работает код. Через неделю забудешь.

**Решение:** Правило "объясни каждую строку". Не копируй, пока не понял.

---

### Ошибка 2: "Выучил всю теорию — теперь буду практиковаться"

**Проблема:** Теория без практики забывается за 2 дня.

**Решение:** Теория только для текущей задачи. Учи то, что нужно прямо сейчас.

---

### Ошибка 3: "Сломал — не записал — забыл"

**Проблема:** Через месяц наступишь на те же грабли.

**Решение:** Dev-log сразу после решения проблемы. Не откладывай.

---

### Ошибка 4: "Git потом настрою"

**Проблема:** "Потом" не наступает. Код теряется, прогресс не виден.

**Решение:** Git с первого дня. Даже если криво — коммить.

---

### Ошибка 5: "Сравню себя с другими"

**Проблема:** Кто-то учится быстрее, у кого-то больше времени. Ты бросаешь.

**Решение:** Сравнивай себя с собой вчерашним. Прогресс есть? Идём дальше.

---

### Ошибка 6: "Брошу, если не получится"

**Проблема:** Не получится с первого раза. Не получится с десятого. Это нормально.

**Решение:** Правило "100 часов". Дай себе 100 часов честной работы. Если через 100 часов не видишь прогресса — тогда бросай. Но не раньше.

## 📊 Метрики прогресса

### Что отслеживать

1. **Количество сниппетов** (цель: 20+ за 6 месяцев)
2. **Количество записей в dev-log** (цель: 30+ за 6 месяцев)
3. **Количество коммитов в Git** (цель: 50+ за 6 месяцев)
4. **Время на сниппет** (должно уменьшаться)
5. **Количество поломок на сниппет** (должно быть 3+)

### Как отслеживать

**Раз в неделю:**
- Открой dev-log, посчитай записи
- Открой Git, посчитай коммиты
- Открой папку snippets, посчитай папки

**Раз в месяц:**
- Перечитай dev-log за месяц
- Выбери 1 старый сниппет, попробуй написать по памяти
- Оцени прогресс: стало легче?
