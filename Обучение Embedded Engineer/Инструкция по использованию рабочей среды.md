## 💻 Ноутбук (Work / Home)

### Базовая настройка (делается один раз)

**1. Драйверы USB-мостов:**
- **Arduino UNO:** CH340 или ATmega16U2 (определяется сразу)
- **ESP32 DevKit:** CP2102 или CH340
- **Как проверить:** `lsusb` (Linux) или Диспетчер устройств → Порты COM и LPT (Windows)
- **Если не видно:** переустанови драйвер, смени USB-кабель (90% проблем — в кабеле)

**2. Софт:**
- **VS Code** — основной редактор
- **PlatformIO** — расширение для VS Code (не Arduino IDE!)
- **Git** — система контроля версий
- **Obsidian** — база знаний
- **GitHub Desktop** (опционально) — если консольный Git бесит

**3. Структура папок на диске:**
```
D:\embedded\
├── projects\          ← PlatformIO проекты
│   ├── arduino\
│   └── esp32\
├── knowledge\         ← Obsidian vault
│   ├── snippets\
│   ├── dev-log\
│   ── theory\
└── docs\              ← даташиты, схемы, скриншоты
```

### Разделение Work / Home

Если работаешь на двух ноутах:
- **Git — твой мост.** Всё, что написано на одном ноуте, пушится в GitHub, пуллится на другом.
- **Obsidian vault храни в Git.** Плагин Obsidian Git синхронизирует заметки автоматически.
- **PlatformIO проекты — только в Git.** Не копируй папки флешками.

**Правило:** Перед началом сессии на любом ноуте — `git pull`. Перед завершением — `git push`.

## 🟢 Arduino IDE — когда использовать, когда забыть

### Когда использовать:
- **Только для проверки библиотек.** Если не уверен, работает ли библиотека с твоим железом — открой Arduino IDE, залей пример.
- **Монитор порта.** Иногда Serial Monitor в Arduino IDE работает стабильнее, чем в PlatformIO.
- **Быстрый тест на 5 минут.** Когда лень создавать PlatformIO проект.

### Когда ЗАБЫТЬ:
- **Для основных проектов.** Arduino IDE скрывает слишком много. Ты не поймёшь, как работает код.
- **Для ESP32 + ESP-IDF.** В Arduino IDE ESP-IDF недоступен в полном объёме.
- **Для серьёзной разработки.** Нет нормального автодополнения, рефакторинга, интеграции с Git.

**Вердикт:** Arduino IDE — это "аварийный инструмент". Держи установленным, но не открывай без крайней необходимости.

##  VS Code + PlatformIO — основная среда

### Почему PlatformIO, а не Arduino IDE:
- Поддержка **ESP-IDF** (твой основной фреймворк по плану)
- Нормальное **автодополнение** и переход к определениям
- Интеграция с **Git** из коробки
- Управление **библиотеками** через `platformio.ini`
- **Монитор порта** встроен прямо в VS Code

### Структура PlatformIO проекта:
```
my-project/
── include/          ← заголовочные файлы (.h)
├── lib/              ← локальные библиотеки (например, LiquidCrystalRus)
├── src/
│   └── main.cpp      ← твой код
├── test/             ← юнит-тесты (потом)
├── platformio.ini    ← конфиг проекта (платы, библиотеки, флаги)
── README.md         ← описание проекта
```

### Типовой `platformio.ini` для Arduino:
```ini
[env:uno]
platform = atmelavr
board = uno
framework = arduino
monitor_speed = 9600
lib_deps = 
    liquidcrystalrus
```

### Типовой `platformio.ini` для ESP32:
```ini
[env:esp32dev]
platform = espressif32
board = esp32dev
framework = espidf
monitor_speed = 115200
build_flags = 
    -DCONFIG_ESP_TASK_WDT_TIMEOUT_S=10
```

### Горячие клавиши (выучи наизусть):
- `Ctrl+Shift+B` — собрать проект
- `Ctrl+Alt+U` — загрузить прошивку
- `Ctrl+Alt+S` — открыть монитор порта
- `Ctrl+Shift+P` → `PlatformIO: Clean` — очистить сборку (если глючит)

### Типичные проблемы и решения:

| Проблема | Решение |
|----------|---------|
| Порт не виден | Переподключи USB, проверь драйвер, смени кабель |
| Ошибка компиляции после смены платы | `PlatformIO: Clean` → пересобрать |
| Монитор порта показывает кракозябры | Проверь `monitor_speed` в `platformio.ini` |
| Библиотека не находится | Добавь в `lib_deps` в `platformio.ini` |
| "Permission denied" на порту (Linux) | `sudo usermod -a -G dialout $USER` → перезагрузка |

## 📓 Obsidian + Git — база знаний

### Почему Obsidian:
- **Markdown** — тот же формат, что и README на GitHub
- **Локальное хранение** — файлы лежат у тебя на диске, не в облаке
- **Связи между заметками** — можно связать сниппет с теорией
- **Git-интеграция** — вся история изменений сохраняется

### Структура vault:
```
knowledge/
├── snippets/
│   ├── arduino/
│   │   ├── lcd-1602.md
│   │   └── dht11.md
│   └── esp32/
│       ├── blink.md
│       └── i2c-scanner.md
├── dev-log/
│   └── 2026-06-09-lcd-problems.md
── theory/
│   ├── ohm-law.md
│   └── i2c-protocol.md
└── templates/
    ├── snippet.md
    └── dev-log-entry.md
```

### Проблема с Git в Obsidian

**Симптом:** Плагин Obsidian Git работает криво, коммиты не пушатся, конфликты.

**Решение (по приоритету):**

1. **Используй консольный Git** (надёжнее всего):
   ```bash
   cd ~/knowledge
   git add .
   git commit -m "Добавил сниппет LCD 1602"
   git push
   ```

2. **GitHub Desktop** (если консоль бесит):
   - Открой папку vault в GitHub Desktop
   - Коммить и пушь через графический интерфейс

3. **Загрузка с телефона** (крайний случай, как ты делаешь сейчас):
   - Зайди на GitHub.com через браузер
   - Загрузи файлы вручную
   - **Минус:** нет истории, нет веток, неудобно

**Правило:** Выбери один способ и используй только его. Не прыгай между консолью, плагином и телефоном.

##  Нейронки: Qwen, DeepSeek, Perplexity

### Жёсткое разделение ролей

| Нейронка | Роль | Когда использовать |
|----------|------|---------------------|
| **Qwen** | **Код-ревьюер и наставник** | Написать код, объяснить строку, найти ошибку |
| **DeepSeek** | **Преподаватель теории** | Объяснить концепцию, протокол, архитектуру |
| **Perplexity** | **Библиотекарь** | Найти функцию в docs, даташит, решение ошибки |

### Правила работы с нейронками

**Правило 1: Одна задача — одна нейронка.**
Не спрашивай Qwen про теорию I2C. Не проси DeepSeek написать код. Не ищи в Perplexity объяснения.

**Правило 2: Нейронка не пишет код за тебя.**
Ты пишешь код сам. Нейронка только:
- Проверяет твой код
- Объясняет непонятные моменты
- Предлагает, как улучшить

**Правило 3: Проверяй всё, что говорит нейронка.**
Нейронки галлюцинируют. Особенно с редкими библиотеками и специфичным железом.

### Промпт-шаблоны

**Для Qwen (код):**
```
Я пишу [задача] на [Arduino/ESP-IDF].
Вот мой код:
[код]

Проверь код и:
1. Укажи на ошибки
2. Объясни каждую строку, которую я могу не понять
3. Предложи, как улучшить
4. Не переписывай код полностью — только правки
```

**Для DeepSeek (теория):**
```
Объясни [концепция] простыми словами.
Требования:
1. Начни с аналогии из реальной жизни
2. Покажи, как это работает на уровне битов/байтов
3. Приведи минимальный пример кода
4. Укажи типичные ошибки
```

**Для Perplexity (поиск):**
```
Найди в официальной документации [ESP-IDF/Arduino]:
1. Функцию для [задача]
2. Пример использования
3. Ссылку на источник
```

### Как интегрировать три нейронки в один workflow

**Пример: подключение DHT11 на ESP32**

1. **Perplexity:** "Найди в ESP-IDF docs функцию для работы с GPIO с таймингами микросекунд"
   → Нашёл: `esp_timer_get_time()`, `gpio_set_level()`

2. **DeepSeek:** "Объясни, как работает single-wire протокол DHT11"
   → Объяснил: мастер тянет линию low на 18ms, датчик отвечает бит за битом

3. **Ты:** Пишешь код сам, используя информацию из шагов 1-2.

4. **Qwen:** "Проверь мой код чтения DHT11 на ESP-IDF"
   → Нашёл ошибку в таймингах, предложил правку

5. **Ты:** Исправляешь, тестируешь, записываешь в dev-log.

## 🔧 Железо и макетки

### Организация рабочего места

**Минимальный набор:**
- Макетка 830 точек (для Arduino + LCD)
- Макетка 400 точек (для датчиков, когда придёт ESP32)
- Набор перемычек (папа-папа, папа-мама)
- Мультиметр
- Пинцет (для мелких деталей)
- Лупа (для чтения маркировки SMD)

### Правила подключения

1. **Питание — последним.** Сначала собери схему, проверь глазами, потом подключай USB.
2. **Цветовая кодировка:**
   - Красный — 5V / 3.3V
   - Чёрный — GND
   - Остальные цвета — сигнальные пины
3. **Подпись пинов.** Если используешь нестандартные пины — наклей стикер на макетку.
4. **Фото перед разборкой.** Всегда фоткай рабочую схему перед тем, как разобрать.

### Хранение компонентов

- **Сортируй по типам:** резисторы, LED, датчики, провода
- **Подписывай коробки/пакетики**
- **Не выбрасывай сгоревшие компоненты** — они полезны для тестов (что будет, если...)

## ⚠️ Типичные ошибки и как их избежать

### Ошибка 1: "Настрою среду идеально — потом начну учиться"

**Проблема:** Ты тратишь неделю на настройку VS Code, тем, плагинов. Код не пишешь.

**Решение:** Минимальная настройка за 30 минут. Остальное — по мере необходимости.

---

### Ошибка 2: "Храню код в разных местах"

**Проблема:** Часть кода на одном ноуте, часть на другом, часть в Arduino IDE, часть в PlatformIO.

**Решение:** Один репозиторий Git. Всё остальное — хаос.

---

### Ошибка 3: "Использую все нейронки сразу"

**Проблема:** Qwen написал код, DeepSeek объяснил теорию, Perplexity нашёл docs. Ты запутался, кто что сказал.

**Решение:** Одна задача — одна нейронка. Жёсткое разделение ролей.

---

### Ошибка 4: "Не фоткаю схемы перед разборкой"

**Проблема:** Разобрал макетку, через неделю нужно повторить — не помнишь, как было подключено.

**Решение:** Фото перед разборкой. Без исключений.

---

### Ошибка 5: "Пишу dev-log раз в неделю"

**Проблема:** Забыл детали проблем, решения записаны поверхностно.

**Решение:** Dev-log сразу после решения проблемы. 5 минут сейчас = 30 минут экономии потом.

## 🎯 Финальные рекомендации

1. **Среда — это инструмент, а не цель.** Не трать на настройку больше, чем на обучение.
2. **Git — твой спасательный круг.** Коммить часто, пушить регулярно.
3. **Obsidian — твой второй мозг.** Записывай всё, что понял. Через 3 месяца это станет бесценным.
4. **Нейронки — ассистенты, а не авторы.** Ты учишься, они помогают. Не наоборот.
5. **Фотографируй схемы.** Память подводит, фото — нет.

**Помни:** Идеальной среды не существует. Существует среда, которая работает достаточно хорошо, чтобы ты мог учиться. Настрой базовый минимум и начни кодить. Остальное приложится.
