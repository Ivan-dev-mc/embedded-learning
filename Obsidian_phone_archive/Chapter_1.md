### 🧠 Суть

Среда разработки должна **компилировать и шить**, а не отвлекать на настройку. PlatformIO — это диспетчер, который управляет тулчейном, а не сам компилятор.

### 🔧 Что изучено

#### Тулчейн (Toolchain)

**Определение:** Набор программ, которые превращают C-код в бинарник для ESP32.

| Компонент | Что делает | Аналогия |
|-----------|------------|----------|
| **Препроцессор** | Разворачивает `#include` и макросы | Подготовка чертежа |
| **Компилятор** (`xtensa-esp32-elf-gcc` / `clang`) | C-код → ассемблер → машинный код (`.o` файлы) | Раскройщик деталей |
| **Линкер** (`ld`) | Собирает `.o` файлы, раскладывает по памяти Flash/RAM | Сборщик узлов |
| **Упаковщик** (`objcopy`, `esptool.py`) | Создаёт итоговый `.bin` с заголовками | Упаковщик готового изделия |
| **Прошивальщик** | Загружает `.bin` в ESP32 по UART | Доставка на объект |

#### Где ловить ошибки

| Этап | Что проверяет | Типичные ошибки |
|------|---------------|-----------------|
| **Компиляция** | Синтаксис, наличие функций | `undefined reference`, `syntax error` |
| **Линковка** | Раскладка по памяти | `region overflowed`, `section too large` |
| **Упаковка** | Конфигурация разделов | `partition table error` |
| **Прошивка** | Доступ к порту | `Failed to connect`, `timeout` |
| **Выполнение** | Работа на железе | `panic`, `Guru Meditation`, `Watchdog timeout` |

**Ключевое правило:**
- **Статика** (глобальные переменные, код) → проверяется линкером **ДО** прошивки
- **Динамика** (стек, malloc, куча) → проверяется **ПОСЛЕ** прошивки при выполнении

#### Структура ESP-IDF проекта

my_project/
├── platformio.ini          # Паспорт проекта (плата, фреймворк, настройки)
├── sdkconfig               # Автогенерируемый конфиг (не править вручную!)
├── sdkconfig.defaults      # Фиксированные настройки (держать в Git)
├── main/
│   ├── CMakeLists.txt      # Что компилировать внутри main/
│   └── main.c              # Точка входа: void app_main(void)
└── build/                  # Генерируется автоматически (не коммитить)

**Почему `app_main()` не возвращает значение:**
- Это не `main()` из desktop C
- После входа управление перехватывает FreeRTOS
- Если функция завершится → краш или уход в idle
- Код должен: либо `while(1)`, либо создать задачи и выйти

#### ESP-IDF vs Arduino vs PlatformIO

| Инструмент | Что это | Когда использовать |
|-------------|---------|-------------------|
| **ESP-IDF** | Официальный фреймворк Espressif | Продакшен, полный контроль, обучение |
| **Arduino Core** | Обёртка поверх IDF | Быстрый прототип, простые проекты |
| **PlatformIO** | Сборочная система (диспетчер) |统一管理 для IDF/Arduino, CI/CD |

#### Когда будет доступ к ноутбуку:
1. Установить VS Code + PlatformIO
2. Установить драйверы CP210x или CH340 (по чипу на плате)
3. Создать проект: `platformio.ini` с `framework = espidf`
4. Залить шаблон с `app_main()`
5. Зажечь встроенный LED (GPIO 2) через `gpio_set_level()`

**Пример кода:**
```c
#include "driver/gpio.h"

#define LED_PIN GPIO_NUM_2

void app_main(void) {
    gpio_config_t io_conf = {
        .pin_bit_mask = (1ULL << LED_PIN),
        .mode = GPIO_MODE_OUTPUT,
        .pull_up_en = GPIO_PULLUP_DISABLE,
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type = GPIO_INTR_DISABLE
    };
    gpio_config(&io_conf);

    while (1) {
        gpio_set_level(LED_PIN, 1);
        for(volatile int i=0; i<100000; i++);
        gpio_set_level(LED_PIN, 0);
        for(volatile int i=0; i<100000; i++);
    }
}
```

### 💥 Типичные сбои

| Проблема | Причина | Решение |
|----------|---------|---------|
| **Порт не виден** | Нет драйвера / нет прав | `lsusb` (Linux) / Диспетчер устройств (Windows), reinstall CP210x/CH340 |
| **Permission denied** | Нет прав на `/dev/ttyUSB*` | `sudo usermod -a -G dialout $USER` (Linux) |
| **Failed to connect** | Плата не в режиме загрузки | Зажать BOOT, нажать RESET, отпустить BOOT |
| **Сборка падает** | Ошибка в коде/настройках | Читать лог, смотреть на какой стадии (компиляция/линковка) |

### 📝 Вопросы для самопроверки

1. **Где хранятся настройки периферии в ESP-IDF?**  
   → `sdkconfig` (автогенерируемый), править через `menuconfig` или `sdkconfig.defaults`

2. **Что произойдёт, если объявить `uint8_t buffer[100000]` и он не влезет в RAM?**  
   → Ошибка на этапе **линковки**: `region dram0_0 overflowed`, `.bin` не создастся

3. **Почему нельзя просто скопировать `.c` файл в ESP32?**  
   → ESP32 понимает только машинный код (нули и единицы), `.c` — это текст для человека

4. **Чем PlatformIO отличается от Arduino IDE?**  
   → PlatformIO — диспетчер тулчейна с единым конфигом, Arduino IDE — упрощённая обёртка
