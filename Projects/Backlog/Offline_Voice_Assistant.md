# 🎙️ Offline Voice Assistant (JARVIS-level)

## 📋 Назначение
Локальный голосовой ассистент с пониманием контекста твоей экосистемы, проактивным мониторингом и диалоговыми способностями.
**Не просто команды** — а **интеллектуальный помощник инженера**, который знает твои проекты, логи и может предложить решение.

## 🎯 Боль
- Руки заняты (пайка, код), а надо выполнить действие или получить информацию
- Не хочу отправлять голос/данные в облако (приватность, автономность)
- Существующие ассистенты не понимают embedded-контекст («почему сканер глючит?», «какой статус VPN?»)
- Хочется **проактивной помощи**: «Заметил аномалию, предлагаю решение»
- Нужен **диалог**, а не просто команды: «Почему это произошло?» → объяснение

## 💡 Решение (полная версия)
Python-система на Pi400/ПК с многоуровневой архитектурой:

### Уровень 1: Распознавание (Speech-to-Text)
- Запись аудио (кнопка ESP32 или Keyword Spotting)
- Whisper.cpp (локально, русская модель tiny/small)
- Текст → следующий уровень

### Уровень 2: Понимание (NLP + LLM)
- **Простой парсер** (MVP): ключевые слова → действия
- **LLM + RAG** (v2.0): 
  - Ollama + Llama 3.1 8B на Pi400
  - Векторная БД (FAISS/Chroma) с твоими Obsidian-заметками
  - Понимание контекста: «сканер» → `[[Runout_Scanner.md]]`

### Уровень 3: Доступ к экосистеме
- **Чтение логов**: последние ошибки устройств
- **MQTT-интеграция**: статусы в реальном времени
- **Git-операции**: commit, push, log
- **Файловая система**: Obsidian, конфиги, проекты

### Уровень 4: Действия
- **Простые**: запуск программ, заметки, поиск
- **Комплексные**: «подготовь рабочее место» → 5-10 действий
- **Диагностика**: «проверь сканер» → анализ логов → предложение решения

### Уровень 5: Проактивность (v3.0)
- Фоновый мониторинг метрик (сеть, логи, устройства)
- Обнаружение аномалий («трафик упал на 40%»)
- Предложения: «Вероятная причина X, запустить диагностику?»

### Уровень 6: Диалог и память (v4.0)
- История разговоров (SQLite)
- Контекст: «это» = последний упомянутый проект
- Обучение: «ты всегда чинил это так» → предложение

### Обратная связь
- Текст на экране
- Голосовой ответ (Silero TTS, опционально)
- Уведомления в Obsidian/Telegram

### Компоненты (для Варианта Б)
| Компонент | Функция | Подключение |
|-----------|---------|-------------|
| ESP32-S3 | Wi-Fi клиент, триггер записи, индикация | USB 5V |

- Для русского: `whisper-tiny.ru` (~700 МБ) или `small.ru` (~2 ГБ)
- Для LLM: Llama 3.1 8B требует ~8 ГБ RAM (квантованная q4_0)
- RAG: FAISS/Chroma для векторного поиска по заметкам

### Пример кода: Ядро распознавания (MVP)
```python
import subprocess, json, os

WHISPER_BIN = "./whisper.cpp/main"
MODEL = "./models/ggml-tiny.ru.bin"

def transcribe(audio_path: str) -> str:
    cmd = [
        WHISPER_BIN,
        "-m", MODEL,
        "-f", audio_path,
        "-l", "ru",
        "-oj",
        "-otxt"
    ]
    result = subprocess.run(cmd, capture_output=True, text=True)
    
    if os.path.exists(audio_path + ".json"):
        with open(audio_path + ".json", "r", encoding="utf-8") as f:
            data = json.load(f)
            return data.get("text", "").strip()
    return ""
```

### Пример кода: Простой парсер (MVP)
```python
def parse_intent(text: str) -> dict:
    text = text.lower()
    
    if any(kw in text for kw in ["замет", "запиш", "сохрани"]):
        note = text.split("замет")[-1].strip()
        return {"action": "add_note", "text": note}
    
    if "открой" in text and "терминал" in text:
        return {"action": "launch", "app": "terminal"}
    
    if "закоммить" in text or "git push" in text:
        return {"action": "git", "cmd": "add_commit_push"}
    
    return {"action": "unknown", "raw": text}
```

### Пример кода: LLM + RAG (v2.0)

from langchain.vectorstores import FAISS
from langchain.embeddings import HuggingFaceEmbeddings
from langchain.llms import Ollama
from langchain.chains import RetrievalQA

# Инициализация (один раз при старте)
embeddings = HuggingFaceEmbeddings(
    model_name="sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
)
vectorstore = FAISS.load_local("./obsidian_index", embeddings)
llm = Ollama(model="llama3.1:8b", base_url="http://localhost:11434")

def query_with_context(text: str) -> str:
    # Поиск релевантных заметок
    docs = vectorstore.similarity_search(text, k=3)
    context = "\n\n".join([d.page_content for d in docs])
    
    # Формирование промпта
    prompt = f"""
    Ты — ассистент embedded-инженера. Используй контекст из его заметок.
    
    Контекст:
    {context}
    
    Вопрос: {text}
    
    Дай конкретный, технически точный ответ.
    """
    
    return llm(prompt)

### Пример кода: Доступ к логам (v2.0)
```python
def get_device_logs(device: str, hours: int = 24) -> list:
    """Чтение последних логов устройства из базы/файлов"""
    logs = []
    log_path = f"./logs/{device}.log"
    
    if os.path.exists(log_path):
        with open(log_path, "r", encoding="utf-8") as f:
            lines = f.readlines()
            # Последние 50 строк
            logs = [line.strip() for line in lines[-50:]]
    
    return logs

def diagnose_device(device: str) -> str:
    """Анализ логов и предложение решения"""
    logs = get_device_logs(device)
    
    if not logs:
        return f"Логи {device} не найдены"
    
    # Простой анализ паттернов
    if "TIMEOUT" in " ".join(logs):
        return f"Обнаружены TIMEOUT в {device}. Вероятная причина: проблема с соединением. Рекомендую проверить wiring и подтяжки."
    elif "NOT FOUND" in " ".join(logs):
        return f"Устройство не найдено. Проверь питание и адрес на шине."
    else:
        return f"Критических ошибок не обнаружено. Последние логи: {logs[-3:]}"
```

### Пример кода: MQTT-интеграция (v2.0)
```python
import paho.mqtt.client as mqtt
import json

MQTT_BROKER = "192.168.1.100"
MQTT_PORT = 1883

def get_device_status(device: str) -> dict:
    """Получение статуса устройства через MQTT"""
    client = mqtt.Client()
    client.connect(MQTT_BROKER, MQTT_PORT, 60)
    
    status = {}
    
    def on_message(client, userdata, msg):
        nonlocal status
        status = json.loads(msg.payload.decode())
    
    client.on_message = on_message
    client.subscribe(f"ecosystem/{device}/status")
    client.loop_start()
    
    # Ждём ответ 2 сек
    import time
    time.sleep(2)
    client.loop_stop()
    client.disconnect()
    
    return status
```

### Пример кода: ESP32 триггер (опционально)
```cpp
#include <WiFi.h>
#include <HTTPClient.h>

const char* ssid = "YOUR_WIFI";
const char* password = "YOUR_PASS";
const char* serverUrl = "http://192.168.1.100:5000/start_recording";

void setup() {
  pinMode(4, INPUT_PULLUP);  // Кнопка
  pinMode(5, OUTPUT);        // RGB LED
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) delay(500);
}

void loop() {
  if (digitalRead(4) == LOW) {  // Нажатие
    digitalWrite(5, HIGH);      // LED: жёлтый (запись)
    
    HTTPClient http;
    http.begin(serverUrl);
    int code = http.POST("");
    http.end();
    
    if (code == 200) {
      // Успех — зелёный
      digitalWrite(5, LOW);
    } else {
      // Ошибка — красный
      digitalWrite(5, HIGH);
    }
    
    delay(3000);  // Держим 3 сек для записи
    digitalWrite(5, LOW);  // Готов
  }
}
```

## 🐛 Отладка и диагностика

| Инструмент | Назначение |
|------------|------------|

| `ollama run llama3.1:8b` | Тест LLM: прямой диалог |
| `mosquitto_sub -t "ecosystem/#"` | Мониторинг MQTT-топиков |

## ⚠️ Риски и решения

| Риск | Вероятность | Решение |
|------|-------------|---------|
| Распознавание медленное (3-5 сек) | 🔴 Высокая | Использовать `tiny` модель, кэширование модели в RAM, показывать индикатор «думаю» |
| LLM требует много RAM (8+ ГБ) | 🟡 Средняя | Использовать квантованную модель (q4_0), запускать только когда нужно, закрыть другие приложения |
| RAG медленно ищет | 🟡 Средняя | Индексация Obsidian раз в сутки (фоновая задача), кэширование частых запросов |
| Микрофон ловит шум цеха | 🟡 Средняя | Кнопка активации (не Keyword Spotting), направленный микрофон, шумоподавление (RNNoise) |
| LLM «галлюцинирует» | 🟡 Средняя | Строгий промпт с контекстом, проверка фактов по логам, fallback на простой парсер |
| Сложность отладки | 🔴 Высокая | Логирование каждого этапа (распознавание → понимание → действие), отдельные логи для LLM |

## 💡 Инсайты

> [!tip] Про приватность #insight
> «Локальный ассистент — это не про «круче». Это про контроль: твои слова не уходят в облако, не анализируются, не продаются. Инженер выбирает инструменты, а не подчиняется им».

> [!example] Почему whisper.cpp, а не облачный API? #insight
> «Облако быстрее и точнее — но требует интернета, аккаунта, телеметрии. Локально — медленнее, но автономно и приватно. Выбор зависит от задачи: для цеха/учёбы автономность важнее скорости».

> [!success] Про парсинг vs LLM #insight
> «Не нужно сразу подключать большую модель. 80% команд — это шаблоны: «открой Х», «запиши У». Простой парсер на ключевых словах работает мгновенно, не требует 8 ГБ RAM и понятен в отладке. LLM — для сложных запросов с контекстом».

> [!note] Про RAG #insight
> «RAG (Retrieval-Augmented Generation) — это не «обучение модели». Это «поиск релевантных заметок + передача в LLM». Модель остаётся той же, но получает контекст из твоих Obsidian-заметок. Дешевле и быстрее дообучения».

> [!warning] Про проактивность #insight
> «Проактивный ассистент — это не «умнее». Это «внимательнее». Он не угадывает мысли, а мониторит метрики и применяет правила. Инженерия, а не магия».
