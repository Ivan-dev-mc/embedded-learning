# 🖥️ PC Macro Pad (Физический Stream Deck)

## 📋 Назначение
Автономное USB-устройство на ESP32-S3, эмулирующее клавиатуру/мышь для автоматизации рутины на ПК. Заменяет мышечную память на физические кнопки с динамическими профилями.

## 🎯 Боль
- Постоянное переключение контекста: IDE ↔ терминал ↔ браузер ↔ Obsidian
- Ручной ввод однотипных команд (`git commit`, `pio run`, `docker compose up`)
- Хоткеи забываются при редком использовании
- Хочется тактильного контроля без взгляда на монитор

## 💡 Решение
ESP32-S3 с Native USB работает как стандартное HID-устройство (клавиатура + мультимедиа). Не требует драйверов на ПК.
- 6 программируемых кнопок + 1 энкодер
- OLED показывает текущий профиль и назначение кнопок
- Профили переключаются Long Press или комбинацией
- Настройка через массивы в коде (позже → конфигуратор)

## 🏗 Архитектура устройства

### Компоненты
| Компонент | Функция | Подключение |
|-----------|---------|-------------|
| ESP32-S3 | Ядро, Native USB HID, логика профилей | USB-C (питание + данные) |
| 6x Тактовые кнопки | Триггеры макросов | GPIO 1–6, internal pull-up |
| Энкодер KY-040 | Громкость / Скролл / Профили | GPIO 7 (CLK), GPIO 8 (DT), GPIO 9 (SW) |
| OLED 0.96" I2C | Визуализация профиля и маппинга | GPIO 21 (SDA), GPIO 22 (SCL) |

### Электрическая схема
[USB-C 5V] ──► [ESP32-S3 VBUS] (Native USB, внешнее питание не нужно)
                      │
                      ├── GPIO 1–6 ──[Кнопки]── GND
                      ├── GPIO 7–9 ──[Энкодер]── GND
                      └── GPIO 21/22 ──[OLED I2C]── 3.3V/GND

⚠️ **Важно:** Использовать только ESP32-S3. ESP32-WROOM не имеет Native USB и не может работать как HID без внешних мостов.

## 💻 Программное обеспечение

### Стек и библиотеки
- **Фреймворк:** ESP-IDF v5.x
- **USB:** Встроенный `tinyusb` + HID descriptors
- **OLED:** `ssd1306` (I2C)
- **Логика:** FreeRTOS (3 задачи: HID Sender, UI Renderer, Button Scanner)

### Режимы / Профили
| Профиль | Кн.1 | Кн.2 | Кн.3 | Кн.4 | Кн.5 | Кн.6 | Энкодер |
|---------|------|------|------|------|------|------|---------|
| **💻 Code** | `Ctrl+Shift+P` | `git add .` | `git commit -m "fix"` | `pio run` | `Alt+Tab` | `Ctrl+S` | Громкость |
| **🌐 Web** | `Ctrl+T` | `Ctrl+W` | `Ctrl+Shift+T` | `F5` | `Ctrl+D` | `Ctrl+H` | Скролл |
| **🎮 Media** | Play/Pause | Next | Prev | Vol+ | Vol- | Mute | Яркость |
| **️ System** | `Win+D` | `Win+E` | `Ctrl+Shift+Esc` | `Win+L` | `PrintScreen` | `Win+V` | Профиль ⬇ |

### Алгоритм работы (FreeRTOS)
```
Задача 1: HID_TASK (High Priority)
  - Ожидает события из очереди key_queue
  - Формирует HID Report (modifier + keycodes)
  - Отправляет через tud_hid_keyboard_report()
  - Ждёт 50мс → отправляет "release" (все 0)

Задача 2: UI_TASK (Medium Priority)
  - Раз в 100мс обновляет OLED
  - Рисует сетку 2x3 с иконками/текстом текущего профиля
  - Обрабатывает анимацию нажатия

Задача 3: INPUT_TASK (Low Priority)
  - Сканирует GPIO кнопок с антидребезгом (50мс таймаут)
  - Обрабатывает энкодер (прерывания по CLK/DT)
  - При событии → кладёт в key_queue или меняет current_profile
  - Long-press на энкодер → переключение профиля (сохранение в NVS)
```

## ⚠️ Риски и решения
| Риск | Вероятность | Решение |
|------|-------------|---------|
| USB HID Descriptors сложны | 🟡 Средняя | Использовать готовый пример `examples/peripherals/usb/device/hid` из ESP-IDF |
| Дребезг кнопок ломает макросы | 🔴 Высокая | Аппаратный RC-фильтр (100нФ + 10к) + программный таймаут 50мс |
| Ограничение N-Key Rollover | 🟡 Средняя | HID Keyboard поддерживает до 6 одновременных клавиш. Не слать >6 кодов в репорте |
| Слет профилей при ребуте | 🟢 Низкая | Сохранение `current_profile` в NVS (Non-Volatile Storage) |
| Эргономика корпуса | 🟡 Средняя | Печатать корпус частями, тестировать угол наклона до финальной сборки |

## 💡 Инсайты

> [!tip] Главный вывод #insight
> USB HID на ESP32-S3 — это не «просто клавиатура». Это дескрипторы, репорты и тайминги. Ошибка в 1 байте репорта = ОС игнорирует устройство. Точность важнее скорости.

> [!example] Почему Native USB критичен #insight
> ESP32-WROOM требует UART-USB мост, который не поддерживает HID класс. S3 имеет встроенный контроллер USB OTG — устройство определяется как Keyboard без драйверов. Это разница между костылём и стандартом.

> [!success] Про профили и NVS #insight
> Хранить маппинг в коде — путь к перепрошивке при каждой правке. NVS позволяет менять профили на лету или готовить конфигуратор. Архитектура должна быть открыта для расширения.
